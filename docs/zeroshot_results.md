실행: Colab L4, `colab/zeroshot_nemotron.py`, `colab/transcribe_whisper.py`. 기록: `experiments/results.csv` EXP-001, EXP-002.

삽입을 뺀 오류(치환 + 삭제)만 보면 Nemotron 49.7, yoona-J 20.6이다.

## 해석

1. **yoona-J 오프라인 수치는 운영 기준이 아니다.** 30초씩 잘라 VAD 없이 전사해서, 무음과 긴 녹음에서 지어내기·반복 루프가 폭발했다 (삽입 84%, 루프 6,984자). 운영 서버는 VAD로 이걸 막는다. **기존 모델 기준선은 계속 EXP-000 (운영 서버, test_v1 CER 37.6%)이다**
2. **그래도 yoona-J가 내용은 훨씬 많이 알아듣는다.** 삽입을 뺀 오류가 20.6 대 49.7이다. 구음장애로 이미 학습된 모델이라 당연하다 (26 그룹 5명은 yoona-J 학습 화자이기도 하다)
3. **Nemotron은 틀릴 때 "지어내지 않고 비운다".** 삽입 5%, 반복 루프 8자. 중증 화자에서는 출력이 거의 없거나 비었다 (21-HHS 빈 출력, 음량은 정상). 스트리밍 구조의 장점(지어내기·반복 없음)은 제로샷에서도 보인다
4. **Nemotron 제로샷은 시연에 못 쓴다.** test_v1 기준 53.4% (쉬움 33.7, 어려움 64.6)로 운영 yoona-J 37.6% (쉬움 8.6, 어려움 50.4)보다 나쁘다. **파인튜닝이 필수다.** 고칠 대상은 삽입이 아니라 삭제(못 알아들어서 비우는 것)다
5. **직접 매긴 점수가 쓸 만하다.** 점수와 Nemotron CER의 순위 상관(Spearman) 0.70. 중증 묶음이 확실히 분리된다 (경증 35.8, 중등도 38.9, 중증 88.7). 경증과 중등도 차이는 작다

## 주의

- **정답은 환자 말만 있을 수 있다.** 13분 녹음에 정답이 230자 정도인 파일이 많다. 진행자 말이나 반복 낭독을 받아 적으면 삽입이 된다. 절대값보다 모델 간 비교로 본다
- **앞 600초만 쓴 녹음**(HHS, BHN, YES, LJE, KJW 2명)은 들은 부분까지만 정렬해 채점했다. 13-YES는 정답이 131자로 짧아 CER이 165%로 튄다
- **단어 과제(01) 파일**(13-KJW-M22)은 단어 사이 무음이 길어 Nemotron이 많이 빠뜨렸다 (삭제 87/144)
- **Colab CLI 타임아웃:** 30분 실행 끝에 `colab exec`가 `TimeoutError`로 끝났지만 VM 안 작업은 완료됐다. 이때 CLI 실행 기록이 남지 않아 검사 스크립트가 코드 확인을 못 한다. 학습처럼 긴 작업은 VM 안에서 백그라운드로 돌린다
