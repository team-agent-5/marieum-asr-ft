# 최종 계획 (2026-11-14 작성, 11-26 시연)

## 1. 목표와 판정 기준

- **목표:** 마리음 실시간 음성 인식을 Whisper(yoona-J)에서 **네이티브 스트리밍 모델**로 바꾸고, AI Hub 구음장애 데이터로 직접 파인튜닝한다
- **바꾸는 이유:** 지금 구조는 0.5초마다 구간 전체를 다시 전사한다. 그래서 interim 글자가 final에서 35% 바뀌고, 반복 루프와 지어낸 글자가 생기고, 구간이 길수록 느려진다
- **기준선 (EXP-000, yoona-J):** 22명 대화 모드 CER 37.6% (쉬움 8.6%, 어려움 50.4%)
- **교체 판정 (11-21):** 파인튜닝 모델의 CER이 yoona-J와 비슷하거나 낫고, 글자 뒤집힘·반복·지연이 확실히 좋아지면 교체한다. 아니면 시연은 yoona-J로 하고 새 모델은 "다음 단계"로 소개한다
- **안전장치:** 환경변수 하나로 yoona-J로 되돌릴 수 있게 남긴다

| 데이터 보관 | 이 PC, 외장하드, Google Drive(학습용, 허용 확인됨). 음성·전사는 git에 넣지 않는다 |
| 용어 | train / val / test (dev = val) |
| 난이도 | 사용자가 307명을 직접 들어 0~5점 채점 완료 (`splits/listen_scores_v1.csv`) |

| 분할 (`data_prep/make_splits.py`) | train 268명 (경증 172, 중등도 43, 중증 29, 기준점 24), val 10명 (경증 4, 중등도 3, 중증 3), test_v2 30명 (처음 듣는 사람 23 + 들어 본 사람 7). 같은 사람으로 의심되는 ID 12묶음은 같은 쪽에 둔다 |

## 5. 평가

- **테스트 세트:** `test_v1` 22명 (yoona-J 비교용), `test_v2` 30명 (우리 모델 평가용. 화자당 평가 파일 1개, 20분 넘는 녹음은 앞 600초. 합계 약 380분)
  - `test_v2`의 `track=seen` 7명은 학습에 같은 사람의 다른 녹음이 들어간다. 처음 듣는 사람(`unseen`) 점수와 따로 낸다
- **대표 지표:** 중증 화자의 화자별 평균 CER
- **그 밖:** 묶음별·태그별 CER, interim 글자 뒤집힘 비율, 4세션 지연 p95, 무음에서 지어내기, 반복 루프
- **같은 대본 주의:** 학습에 나온 문장은 따로 보고, 자기소개·자유발화 CER을 따로 낸다
- **점수 검증:** 제로샷 화자별 CER과 사람 점수가 같이 움직이는지 본다. 크게 어긋난 화자만 다시 듣는다
- **기록:** `experiments/results.csv`에 실험 하나당 한 줄

## 6. Colab 흐름

```
[이 PC] 전처리 → tar 묶음 → (제로샷) colab upload / (학습) Google Drive
[Colab] colab new → (학습만) drivemount [사용자 동의] → /content로 복사
        → colab exec (설치·추론·학습, 긴 학습은 VM 안에서 백그라운드)
        → 결과·체크포인트를 Drive에 저장 → colab download (작은 결과) → colab stop
```

- 잔액 131 CU (11-13 기준). 다른 프로젝트 CPU 세션 3개가 켜져 있었다. 작업이 끝나면 반드시 `colab stop` 후 `colab sessions`로 확인한다
- VM은 언제든 회수될 수 있다. 끊기면 Drive 체크포인트에서 이어서 학습한다
